# MapMaker Lesson Player (Lab)

A reusable player for MapMaker lessons. Each lesson is a small data spec: web map, layers, clues and places. The player reads the answers directly from the map data, so nobody has to type up answer keys.

**Live:** https://jsawle.github.io/lessons/

## Where it fits with MapMaker
The player is an entry point into MapMaker, not a replacement for it. It uses the same reviewed MapMaker web maps, and every round and the end screen hand students off to MapMaker ("Investigate … in MapMaker"), opened on the same web map. The game is designed to sit as a tab inside the lesson's Portfolio, next to the MapMaker tab.

## Games
- **Mystery Place** (v1.1.0): students get climate clues and use the map layers to find the place. They score points for distance and for how well their place's data matches the clues.

## Layer access check
Before the map loads, the player tests each web map layer from this website. Any layer that refuses access (for example a service proxy limited to arcgis.com referrers) is skipped, so students never see a sign-in box. Teachers can see the list of skipped layers under Teacher tools (`?teacher=1`).

## URL options
| Parameter | Effect |
|---|---|
| `?teacher=1` | Shows teacher tools: answer key, Teacher Guide check against live data, layer access check, MapMaker handoff test |
| `?seed=7B` | Gives the whole class the same game |
| `?lesson=specs/<file>.json` | Loads a different lesson spec (merged over the built-in default) |
| `?mapmakerApp=<appid>` | Sends the handoff links to a different MapMaker/Atlas app (for distributors, e.g. Esri South Africa) |

## Lesson spec: MapMaker handoff
```json
"mapmaker": { "appId": "0cd1cdee853c413a84bfe4b9a6931f0d", "portalUrl": "https://www.arcgis.com",
              "label": "National Geographic MapMaker", "passLocation": false }
```
`passLocation` adds `&center=lon,lat&level=n` so MapMaker opens at the mystery place. It is off until we've confirmed Atlas accepts those parameters. Use the test link under Teacher tools to check.

## Resource pages (lab)
A mock-up of Support Hub lesson pages, at `resources/`. Live at https://jsawle.github.io/lessons/resources/

**One file per lesson.** Everything comes from `resources/lessons/<id>.json`: the lesson page, its teacher page (`/pages/<id>-teacher`, which holds the answers), the English and Spanish Word student sheets, the Word teacher notes, the how-to video links, the lesson's entry in the AI assistant's knowledge file (Vera's, for MapMaker) and the prompt for a teacher's own AI tool. Change the file and all of them change together.

**Lesson files don't name the app.** A lesson file holds the map, the questions, the answers and the teacher guide. The Atlas app the map opens in, the Hub the pages are published to, the AI assistant, the Google Classroom button, the licence and the product names all live in a lessons settings file, `resources/<name>-lessons.json`, which is merged over the shared settings in `site.json`. There are two: `resources/core-lessons.json`, the default (`lessonSettings.default` in `site.json`), with no product brand, published to the demo Hub site; and `resources/mapmaker-lessons.json`, the MapMaker version. Shared wording in `site.json` writes product names in braces, such as `{openInApp}` and `{appMap}`; they are made from `names.app` (and `names.appFull`) in the lessons settings file, so the wording reads naturally with a product name ("Open in MapMaker", "the MapMaker map") or without one ("Open map", "the map"). A lessons settings file can also set any of them itself in `names`. Objects merge key by key; text, numbers and lists in the lessons settings file replace the shared ones. Pages take `?lessons=<name>` to use another settings file, and the checker and build take `--lessons <name>`.

**Where the answers live.** The lesson page is safe to share with students: it has the map, the questions, the standards and the student sheet, but no answers. The lesson page keeps the teacher notes (before class, common misunderstandings, key words) and links, in that section, to the answer page (`/pages/<id>-teacher`) and the teacher notes Word file, which hold where to find each answer and what to accept. The Lessons page carries a muted "answer notes" link in each card. The team's known-issues notes (`knownIssues`) stay in the lesson file and show on the lab mock-up only, never on the Hub pages. Each answer says where on the map it is found (`answer.where`) and what to accept (`answer.accept`), with a key table only where a count or list is needed. Vera's knowledge file and the AI prompt carry the questions, layers and bookmarks, never the answers.

**Lessons are arranged by unit, not by month.** `site.json` `units` lists each course's units in the order most courses teach them; a lesson's `unit` must be one of them, and `alsoFits` can name others. The Lessons page groups lessons by unit in that order. `status` and `reviewed` stay in the file for the team's own tracking and are not shown on the pages.

**No account, no login, no local save.** The lessons use MapMaker as it is today. Sketches are not saved between sessions, and every question is answered from the map's layers, pop-ups, legend, bookmarks and the Measure tool (miles and feet). Lessons must not depend on a time slider or a filter unless the web map provides one.

**To add a lesson**
1. Copy `resources/lessons/_template.json` to `resources/lessons/<id>.json`, where `<id>` is lower-case words joined by hyphens. Set `"id"` to match.
2. Fill it in. Editors that read JSON Schema (VS Code, for example) flag mistakes as you type, using `resources/schema/lesson.schema.json`.
3. Add the id to `resources/lessons/index.json`.
4. Open `resources/lesson.html?id=<id>`. Any problems show in a red banner at the top.

**To change a lesson**: edit its file, bump `contentVersion` (patch for typos, minor for changed questions, major for a new map) and set `updated`. When it has been checked, set `status` to `reviewed` and fill in `reviewed.by` and `reviewed.date`. Log map or answer problems under `knownIssues`.

**Shared settings** live once in `resources/site.json`: tool names and the map skills they practise, sheet wording (English and Spanish), units for each course, the order of standards, the AI prompt rules, the shared teacher-guide text, the rubric and the versions table. **Lessons settings** live in `resources/<name>-lessons.json`: the product names (`names`), the Atlas app (`atlas`), the help Hub's address, menu and subject and course pages (`hub`), the how-to page for each tool (`tools`), the Hub site the pages are published to and its colours (`hubDemo`), the AI assistant (`assistant`, optional), the Classroom button (`classroom`) and the licence. `core-lessons.json`: no product name ("Open map"), maps open in the Atlas app from www.arcgis.com, no assistant, how-to videos and Report a problem on the MapMaker Educator Support Hub, and an Esri CC BY-NC-SA 4.0 licence statement. `mapmaker-lessons.json`: MapMaker names, the app from mpmkr.maps.arcgis.com, Vera, and the National Geographic Society and Esri licence statement; not published to a Hub site at the moment.

**Checks**: `node resources/tools/validate.mjs` runs the same checker as the page (including that every unit is on the course's list, that `planMonth` and `keyFacts` are gone, and that every answer says where it is found or what to accept), confirms every file is listed in `index.json`, checks the Hub pages built from the files only use HTML that Hub keeps, checks embed cards have a title for screen readers (at most two a page, as Hub's help advises), checks every in-page link has its anchor (with ids unique across pages, the workaround for Esri bug BUG-000178430), checks the site colours have at least 4.5:1 contrast, and checks the versions table in `site.json` matches the code. It does all of this once for each `*-lessons.json` file, and reports any name in braces that nothing fills in.

**Built files** (served by GitHub Pages): the default lessons settings (`core`) build into `resources/dist`, which the publishing notebook reads; every other one builds into `resources/dist/<name>` (MapMaker: `resources/dist/mapmaker`). Each holds `hub-bundle.json` (the Hub pages: Lessons, one lesson page and one teacher page per lesson), `sheets/*.docx` (Word student sheets and teacher notes) and, when there is an assistant, its knowledge file (`assistant.knowledgeFile`; Vera's is `resources/dist/mapmaker/vera_mapmaker_lessons.txt`). `resources/dist` also holds `publish_to_hub.ipynb` (the publishing notebook). GitHub rebuilds and commits them after every change to `main`, so nobody builds them by hand. To build locally: `npm install --no-save docx@9.7.1`, then `node resources/tools/build-dist.mjs --all` (or `--lessons <name>` for one).

**Publishing to the Hub demo site** (`hubDemo` in `core-lessons.json`: the Lessons demo site, lessons-gis-4-schools.hub.arcgis.com (renamed from mapmakerlessons-gis-4-schools on 22 October 2026))
1. In an ArcGIS Notebook signed in as the site's owner, paste all of `resources/tools/publish_to_hub.py` (raw: `https://raw.githubusercontent.com/jsawle/lessons/main/resources/tools/publish_to_hub.py`) into one cell, or upload `dist/publish_to_hub.ipynb`.
2. Run it with `DRY_RUN = True`: it backs up the site and prints the plan. Nothing is written.
3. Set `DRY_RUN = False` and run it again. It downloads every Word file from GitHub first (trying again if GitHub answers with a temporary error, and stopping before any Hub change if it still can't), uploads them as Word items, creates or updates two Hub Pages per lesson (the lesson page and its teacher page) plus a Lessons page, registers each page in the site's pages list, sets the site colours from `hubDemo.theme`, shares everything and checks its work. If the site editor has an unpublished draft, the notebook backs it up and sets the same colours in it, because publishing a draft copies its colours over the live site. Set `SET_COLOURS = False` to leave the colours alone.
4. Republish the site (Edit layout, then Save/Publish) and add a "Lessons" menu link to `/pages/lessons`.
Run it again after any lesson change: it updates the same pages and Word items. Edit the lesson file, not the Hub page; the page is rebuilt from the file. Preview any Hub page first at `resources/hub-preview.html?page=<slug>`.

**Vera and the AI prompt**: Vera is in the MapMaker version only; the unbranded version has the prompt alone. Vera's chat page (`assistant.url` in `mapmaker-lessons.json`, currently the lab copy; leave `assistant` out for lessons with no assistant) is not embedded anywhere: the Lessons page has an Ask Vera button. Each lesson page has an "Ask Vera about this lesson" link that opens it with the lesson named in the message box, and a "Prompt for your own AI" section: `resources/prompt.html` (`aiPrompt.pageUrl` in `site.json`) builds the prompt from the rules in `aiPrompt.rules` and the lesson's map, layers, pop-up contents, bookmarks and questions, and shows it in a scrolling box with a copy button; the Hub page embeds it in a frame card, so the page stays short. Neither Vera's file nor the prompt contains the answers. Vera answers from `vera_mapmaker_lessons.txt` in `resources/dist/mapmaker`. In Copilot Studio, upload it under Knowledge, wait for indexing to finish, then delete the old copy. List every bookmark in `map.bookmarks` and describe what each pop-up really shows in `shows`, because Vera and the prompt write questions only from those.

**Share to Google Classroom** (`classroom` in `mapmaker-lessons.json`): each lesson page has one button, in the hero next to Open in MapMaker; the note under the Word downloads says it shares the map only. It uses Google's script-free share link (`classroom.google.com/share?url=…`), because Hub pages can't run Google's button script, and it shares the lesson's MapMaker map, never the lesson page, which holds the answer notes. The link carries only the address, so the Word sheet isn't included. Google's Classroom branding guidelines decide the rest: the wording "Share to Google Classroom", the official icon on the left (`resources/assets/brand/`, 32 px, unaltered), Roboto Bold (`resources/assets/fonts/`, SIL Open Font License), a 20% black shade on the icon on hover, and the trademark notice in the page footer. Leave `classroom.icon` empty to switch the button off.

**Assessing the answer** (lesson file format 1.7): `site.json` `rubric` holds one shared rubric for the answer to the compelling question, four criteria (Claim, Map evidence, Geographic reasoning, Accuracy) at four levels (1 Beginning to 4 Strong), in plain words. Each lesson adds `assessment.evidence` (one or two sentences on what counts as map evidence for that map, naming the layers, pop-up fields, dates and distances) and `assessment.exemplar` (a model answer at level 4, with every fact traceable to the lesson's answer notes). The rubric appears on "How these lessons work" (no answers there); the rubric, the evidence line and the model answer appear on each answer page, in the Word teacher notes and in the mock-up's teacher view, never on the lesson page, the student sheet or in Vera's file. The student sheet is unchanged: its "Your answer" line already says what a good answer needs (evidence from at least two layers or places), and the sheets have no room for more. The rubric is offered as one option a teacher can use, adapt or ignore; there is no exit ticket or quiz, on purpose: the final answer is the assessment, and a quick check would repeat the sheet's questions.

**About this map, after the teacher notes** (lesson file format 1.9): each lesson's `map.about` is two to four sentences about the map as a whole (the place and period it covers, its main layers and which are off when it opens), shown first under About this map, before the layer table. About this map now comes after Teacher notes on the lesson page and the mock-up, so the inquiry is the first thing under the hero. The lesson page can be shared with students, so `map.about` gives no answers and asks no questions; the checker requires it (150 to 700 characters).

**On the map, then answer** (lesson file format 1.6): each question's `student` text is replaced by `steps` (two to five short map actions, each one thing to open, click, turn on, zoom to or measure, with no question in them) and `ask` (the one to three questions the student writes an answer to). The student sheet, its preview on the Hub page and the mock-up show each question as its title, "On the map:" with the numbered steps, then "Answer:" with the questions, so a student can see what to do before what to answer; the Spanish labels are "En el mapa:" and "Responde:" (`sheetText` in `site.json`). Vera's entry and the AI prompt carry the steps and questions in the same order. The Lessons page cards no longer link to the teacher notes and answers; that link is only in the Teacher notes section of each lesson page.

**For the front of the class** (lesson file format 1.5): every question carries `core` (true on the one question to use if there is only time for one), `minutes`, and `frontOfClass` (the exact clicks and the question to ask, for a teacher on a projector); each lesson has `differentiation` (one support line, one stretch line). The Inquiry section shows all of it; the Word teacher notes repeat the steps under each answer. Shared material (what every lesson includes, materials, preparing, ways to run a lesson) lives on one Hub page, "How these lessons work" (`hubDemo.aboutSlug`), built from `site.json` `teaching`, so lesson pages stay shorter. Report a problem now carries the lesson id (`?lesson=<id>`) so a report says which lesson it is about; the Support Hub feedback form can read that parameter.

**Teacher guide** (lesson file format 1.4): each lesson carries `subjects`, `objectives` (3 to 5 "Students will…" lines), `discussion` (2 to 4 debrief questions) and `resources` (further reading, National Geographic Education first, every link checked). Map skills are derived from the tools the questions use (`tools[].skill` in `site.json`); ways to run the lesson, teacher preparation lines and the materials note are shared text in `site.json` `teaching`. The Teacher notes section on the lesson page and the Word teacher notes show all of it; the answers stay on the answer page. The licence statement lives once in the lessons settings file (`licence` in `mapmaker-lessons.json`) and appears on every page and Word file; from format 1.8 a lesson file gives its own `licence` only when it differs.

**Two-page student sheets** (used by all ten lessons): a lesson with a `studentSupport` block gets a two-page Word sheet with section headings, more room to write and the map credits once at the end. Long sheets keep the writing lines about 7 mm apart and give each question one line fewer, so every sheet still ends on page two (the builder checks the text length; check the page count after a big text change). The block can hold `beforeYouStart` (two or three sentences of context that don't give away answers), `readingTheMap` (what the map's symbols mean, checked against the web map), `tips` (keys of shared tips in `site.json` `sheetText`, such as `popups`) and `reflection` (a closing question). A question can also set `lines`, the number of writing lines under it. Lessons without the block keep the one-page sheet. The sheet previews on the Hub page and the mock-up show the same sections.
